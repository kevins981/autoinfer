## Combination
The comm cards (03 + 10-adapted) target the same exposed mixer AR, so they don't stack: together <= ~+3% if both work, with an open validity question (FP8 activation bytes on the link) and a memory squeeze. Adding a partial megakernel (02) for decode small kernels: <= ~+2-3% more at very large engineering cost. Even stacked optimistically: ~+5-6%, needing three independent large builds, each with low odds. I don't think an honest forecast reaches the bar.

## Recommendation
None of the 15 cards gives a direction whose payoff-if-it-works credibly clears +5% here. The deck targets offloading, MoE/cluster and scheduling overheads, and this stack has already removed those. What's left is the PCIe AR plus GEMMs at the HBM/tensor floor (KB45, KB91, KB100). I request no start grant and return the 20-min seed unused. If the manager wants the most promising sub-5% item tested anyway, it would be card 10-adapted (FP8 activation all-gather + duplicated out_proj, mixed steps only), after a validity ruling on sending FP8 activations over the link and a memory check. Estimate: +1.5-3%, seed-sized first test (microbench of AG vs AR + out_proj full-K at R=128-1024).
