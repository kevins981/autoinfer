# T30-1: two-wave layer-pipelined mixed steps: hide the all-reduce that the per-layer join leaves exposed

Team T30 (explore), leader-30. Champion T29-006, 1062.1 tok/s. Bar: payoff if it works >= 1115.2 (+5%).

## The observation (measured)
- Mixed (prefill) steps are ~36% of GPU time; big ones (pt >= 209) ~19% (probe job 219 on T29-004; job 235 on T29-006).
- In big steps the marginal cost per prompt token is **0.160 ms** (job 235, T29-006, 83 steps, linear fit pt>=209; 0.161 in
  job 219). The parts: W8A8 GEMM ~0.10 (T29 microbench summary2.md, M=512->1024), misc kernels ~0.03 (census of job 199),
  raw host AR 0.072 (KB91). So the costs add up as if they ran in series.
- **AR-off floor (job 244, T30_NOAR=1, every TP all-reduce a no-op; same code, garbage outputs, timing only):** median GPU
  ms/step A -> B: pt 209-400 93.6 -> 62.1 (-31), pt 401-1000 138.6 -> 95.7 (-43), >1000 293 -> 177; marginal
  0.160 -> 0.109 ms/token. Decode -3.0 ms (24.9 -> 21.8); pt 1-208 -8..-14 ms. B has only 24 big steps (n small) and its
  span metric includes queueing (same in both arms). Table: agents/leader-30.w1/ar_floor/RESULT.md.
- **Interpretation:** about a third of big-step time is exposed all-reduce. The champion's token-split chain (T9 ping-pong,
  model.py `_qwen3_5_split_chain`) splits the rows into 2 chunks but joins them at every layer's GDN/attention core. So
  the AR right after out_proj can overlap only the other chunk's small out_proj (gdn_out at M~190: ~40 us vs ~110-200 us
  of AR). The MLP AR before the next join overlaps only the other chunk's in_proj. Under W8A8 the chunk streams also
  stop staggering (KB89). T29-005's event ordering didn't fix it, which fits: ordering inside a joined layer can't create
  the overlap.

## The idea
Remove the join: **two waves that progress independently through all 64 layers**, wave 1 about half a layer behind
wave 0. Wave 0 = the decode rows + the first part of the prompt rows (64-aligned split point); wave 1 = the rest.
- Wave 1's rows of a split sequence are a chunked-prefill continuation. They need wave 0's GDN state / conv state / KV at
  the same layer, and wave 0 has produced them, since it runs ahead. One cross-stream event per layer, on the core only.
- Every AR of one wave then overlaps the other wave's core, MLP or in_proj, i.e. real compute. FP8 GEMMs at these M are
  tensor-bound, and copy-engine DMA coexists with heavy kernels at x1.0-1.12 (T8-001, KB66). This is the regime where
  T9's microbench hid 86-96% at R>=256 (KB67), but now with the dependency structure fixed.
- Same math: rows are independent in GEMMs, norms and ARs. The GDN chunk kernel processes 64-token chunks, so with a
  64-aligned split the continuation should be the same arithmetic (bitwise to be verified; if not, a bounded fp32
  state-passing reorder). Attention reads the KV that wave 0 wrote.

## Roadmap
1. **Attribution (8 GPU-min).** nsys of the champion's big steps on both ranks: which ARs are exposed (mixer vs MLP), per
   layer; host enqueue per layer (the eager GDN core costs ~1.1 ms host/layer, KB89). Plus arm C (VLLM_DMA_SPLIT=0), to
   see what today's split hides. Kill check: if the exposed AR is mostly elsewhere (e.g. rank skew), re-plan.
2. **Prototype (CPU + 12 GPU-min).** Per-wave core calls (GDN chunked with initial state from wave 0; attention metadata
   per wave), two streams, per-layer core events; applied only at pt >= 256. In-server bitwise self-check vs the joined
   chain (eager, like T29_GLUE_CHECK); probe per-class step times vs the champion. Watch host enqueue: running the core
   twice adds host time, and big steps have ~40-70 ms of GPU time over decode to hide it in. If the host binds, trim
   the core's host path (T29 glue lessons) or only apply at pt >= 400.
3. **Tune (10 GPU-min):** split ratio (unequal waves, so that each wave's AR <= the other wave's compute), threshold, lanes.
4. **Validate (25 GPU-min):** same-job ABBA vs T29-006 (4 starts), 128K, GSM8K (reuse if bitwise, else the 1319 A/B).
5. **Official (8 GPU-min).**
Stretch (separate resync): a mid-M (96-400) W8A8 GEMM nearer max(bytes, compute) (bs_gemm is 45-70% above that
roofline at M=96-384, summary2.md). Splitting into waves makes M/2 GEMMs matter more.
