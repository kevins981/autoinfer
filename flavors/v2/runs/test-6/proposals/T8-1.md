# T8-1: a 2-warps/scheduler decode GEMM. The warm-path gap in KB28 is software, not hardware

Team T8 (explore), leader-8. Champion reference: T1-042, 942.2 tok/s.

## The finding the direction rests on (measured, bank/T8-002, job 62)
- KB28 / T1-022 found that L2-warm Marlin at M=48 runs at ~64-68% of the tensor peak, with math-pipe throttle as
  the top stall. The conclusion drawn was "only a multi-day restructure, <= ~1-1.5 ms/step".
- I rebuilt Marlin's inner loop in isolation at M=48: ldmatrix A from SMEM (3 m16 tiles), one FP8 B word per n8 tile
  dequantized by shift/mask and multiplied by the scale, 3 HMMA per n8 tile. Results on GPU0 (locked 2235 MHz):
  - **1 warp per scheduler (Marlin's design): 99.8 TF = 68.4% of peak.** This matches Marlin's warm gate_up exactly
    (8.55 GFLOP / 84.4 us = 101 TF).
  - **2 warps per scheduler: 133.5 TF = 91.5%.**
  - Raw HMMA peak: 145.9 TF.
  - L2-resident cp.async streaming: 4.2 TB/s, so feeding a warm GEMM is not the limit.
- So the warm ceiling is latency with one warp per scheduler. T1-029's 2-warp prototype lost on its load path
  (1.56 TB/s from L2 vs the 4.2 measured here), not on the math.
- Side result (bank/T8-001, job 61): host page size has no effect on PCIe or interference. Copy-engine traffic
  coexists with an HBM-saturating kernel (copies x1.01-1.12, kernel x1.00-1.04). SM-driven host traffic (hostar
  style) slows x1.45 and costs the kernel 6-19%. This bears on the decode AR in stage 2.

## Roadmap
1. **M1, standalone kernel, gate_up shape (<= 8 GPU-min).**
   - Spec: M<=48, FP8 B in Marlin's existing repacked layout and scales (no extra memory, prefill keeps Marlin),
     dequant bit-identical to Marlin (bf16_rn(fp8 x s)), fp32 accumulation, 8 warps/CTA with >= 8 independent MMAs
     per warp, multistage cp.async, deterministic split-K reduction.
   - Gate: warm (88 MB prefetch, as in the champion) <= 72 us vs Marlin 84; cold <= Marlin's 108; max diff vs
     Marlin <= 1 bf16 ulp.
   - Kill: if two design iterations stay above 78 us warm.
2. **M2, every decode shape (<= 10 GPU-min).**
   - Shapes: GDN in_proj and out_proj, attention qkv and o_proj, gate_up, down, the MTP layer.
   - Measure a 16-layer chain with champion-style ARs and L2 prefetch, against the same chain on Marlin.
   - Gate: projected >= 1.5 ms per decode step.
3. **M3, in-server (<= 20 GPU-min).**
   - Dispatch decode-sized Marlin calls (M<=48) to the new kernel inside CUDA graphs; prefill and mixed steps stay on Marlin.
   - Same-job interleaved ABBA vs T1-042 (3+ starts each), gsm8k 50, the 128K request.
   - Gate: >= +3% same-job.
4. **M4, stage 2: wider L2 prefetch (<= 10 GPU-min).**
   - Today only AR windows prefetch, and down_proj (~3.5 ms/step) runs cold.
   - With warm GEMMs ~1.3x faster, each prefetched byte is worth more. Prefetch down_proj from inside the
     gate_up and act phases, where HBM has slack once gate_up turns tensor-bound.
   - Optionally move the decode AR to the copy engines so the prefetch no longer slows it (T8-001).
5. **Official eval (~20 GPU-min)** when M3/M4 beat the champion in every same-job pair.

## Correctness
- Same weights and the same dequantized bf16 values as Marlin (bit-identical dequant), fp32 accumulation. The only
  change is fp32 summation order: split-K across warps and CTAs, the same class as T1-016's tile change.
- Deterministic.
- Checks: max-abs-diff vs Marlin on real activations, gsm8k, acceptance, the 128K request.
- No memory change: the weight tensors are reused as-is.
