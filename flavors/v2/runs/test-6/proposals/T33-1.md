## Card 13 (decompress weights inside the matmul): the only card whose condition clearly holds. Measured (bank/T33-001)
- **Condition:** decode GEMMs are bound by weight bytes. True here, with the T31 e4m3 kernel, which has no dequant and some ALU room.
- **How much redundancy FP8 has (CPU, real checkpoint, 22 tensors across layers 0-63):**
  - The e4m3 exponent field carries 2.57-2.72 bits of entropy out of 4. Byte entropy is 6.5-6.7 bits.
  - A register-decodable code (raw sign+mantissa nibble, 2-3-bit exponent code over a per-128x128-block window, escape side stream) comes to **0.883** of the bytes.
  - The order-0 entropy bound is **0.821**.
  - ZipServ's +22% came from bf16, where the 8-bit exponent compresses to ~3 bits. For FP8 the exponent field has only 4 bits to begin with.
- **What fewer bytes buy (job 295):**
  - Setup: T31's 16-layer AR+prefetch->GEMM chain at M=48, champion prefetch (48 MB hint). The e4m3 kernel runs on all four shapes and reads only the leading f*K rows of each Marlin qweight.
  - This is an upper bound: decoding is free, and the MMA work also falls by the same share.
  - Baseline: champion-like layer 271.8 / 279.4 us (rank 0 / rank 1).

    | f (share of weight bytes read) | us/layer, r0 / r1 | change vs champion-like |
    |---|---|---|
    | 0.88 | 254.0 / 259.6 | -17.8 / -19.8 us |
    | 0.75 | 230.6 / 236.1 | -41 / -43 us |

  - At f=0.88, gate_up on e4m3 beats Marlin (81.7 vs 87.8 us).
- **Payoff ceiling:**

  | code | saving per decode step | decode | e2e |
  |---|---|---|---|
  | 0.883 | ~1.2 ms | -4.8% | **~+3.0%** |
  | 0.82 (entropy bound) | ~1.7 ms | — | **~+4.3%** |

  - Mixed steps are tensor-bound and don't gain.
  - Real decode cost has to come out of these numbers. At M=48, gate_up's MMA phase overlaps its weight stream poorly (KB98), so in-loop ALU work is not free there.
- **Classification: hard limit (math + measured ceiling).** FP8 weights don't carry enough redundancy for card 13 to reach +5% on this stack, even with perfect decoding.
