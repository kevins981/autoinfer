- Prefill: each prefill event costs ~15 ms fixed (about 1,100 small kernels launched one by one from Python between 65 CUDA-graph pieces; GPU idle ~24 ms in a 62 ms step for a 60-token prompt) + ~166 us per prompt token (GEMM compute ~100 us, PCIe all-reduce bytes ~50-70 us). Prefill runs as separate big compute-bound batches through a different code path than decode.

My thesis: the dominant cost is the fixed per-pass cost; the design under-fills each pass. Proposal 'one static row-budgeted step': every engine step is one fixed-size CUDA graph of R rows (e.g. 80-96); rows are allocated by expected value: 16 mandatory rows, speculative rows by chain probability (deeper k, possibly confidence-allocated per sequence), and prompt tokens ride as extra rows of the same weight pass (~0.10 ms/row instead of 166 us + 15 ms/event) with no eager Python path at all.
