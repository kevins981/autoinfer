# Shared KB (manager-owned; confirmed understanding, each entry cites records)

- KB1: In BASE, mixed prefill steps above 96 tokens run without CUDA graphs. Capturing graphs up to 2048 tokens (max_prefill_cudagraph_capture_tokens) gives +2.3% unofficially, much less than the napkin estimate. (T2-001)
- KB2: In this NCCL, all-reduce kernel names (..._RING_LL) don't show the protocol in use; check NCCL_DEBUG's 'proto' log instead. NCCL_PROTO=Simple set by os.environ.setdefault in pynccl.py does take effect (log: proto SIMPLE), but has no measurable effect inside the engine: decode-step NCCL time at 48 rows is 9.92 ms with it vs 9.66 ms for T2-001 and 9.81 ms for BASE. The standalone LL-vs-Simple gap doesn't carry over to the engine, and T1-002's +1.0% was fresh-start noise. (T1-002, reverted; GPU job 33)
- KB3: The MTP drafter's full bf16 lm_head (1.27 GB/GPU) and its logits all-gathers cost ~1.4 ms per decode step. A reduced-vocab draft head over ids [0,65536), split across ranks with a local argmax, gains +1.3% unofficially despite acceptance falling from 2.351 to 2.312. A 98K head or a 4 GiB KV cut costs a concurrent slot (15 instead of 16) and loses. (T2-003, T2-004)
- KB4: Target-side distributed argmax for all-greedy batches is exact and cuts the logits AllGather from 0.934 to 0.053 ms per decode step. Officially confirmed: 712.1 tok/s, +12.0% vs BASE for the T2-001 + T2-004 + T1-006 lineage. Official gains have run about 2x the unofficial gains vs BASE for this lineage. (T1-006)
- KB5: The checkpoint's W8A8 scheme (humming backend; dynamic group-128 e4m3 activations) speeds up mixed-step GEMMs by about 33% at 260 rows and matches Marlin at decode. GSM8K is 93.2-93.6%. It stacks roughly additively with T1-006: official 761.6 tok/s, +19.8% vs BASE. The humming backend's ignore-list substring bug had left MLP gate_up unquantized, and fixing it is needed. (T2-005, T2-006)
- KB6: Decode GPU idle came from host syncs in metadata builds. In the drafter's FlashInfer decode path, planning with a host upper bound and writing the exact metadata on the device cut idle from 1.92 to 0.61 ms/step, +2.3%. Graph-level nsys traces showing host<->GPU dependencies find these; a FLOP/byte cost model doesn't. (T1-008)
- KB7: GDN replay commit (write only the committed fp32 state; replay accepted tokens next step) is exact and removes ~44 MB/layer of L2 write traffic that slowed the following GEMMs. Official 835.1 tok/s, +31.3% vs BASE. (T2-008)
