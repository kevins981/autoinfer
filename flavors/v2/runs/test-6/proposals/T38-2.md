# T38-2 (moonshot, leader-38): a drafter trained for how it is used — self-distilled, recursively trained MTP head

## Context
T38-1 closed (bank/T38-001): decode comm is at PCIe wire time and overlap is zero-sum on this machine (T4-001 etc.);
decode GEMMs are at the DRAM roofline (job 382). With the step cost essentially fixed (~26 ms at 16 x 4 rows), the
remaining multiplier is **tokens per step**: 2.674 at k=3 (official T37-002; per-position cumulative 0.756 / 0.529 / 0.377,
i.e. conditional 0.756, 0.70, 0.71).

## The idea / assumption rejected
The assumption: "the drafter is the checkpoint's MTP head as shipped; drafting quality is a given." That head was trained
by the model authors one step ahead, on their training data, with the target's hidden state as input. We use it (a) on
the target's own greedy outputs (thinking on, chat), and (b) recursively: at depths 2-3 its input is its *own* hidden
state, a distribution it never saw in training. Both are fixable by fine-tuning under the 2026-11-08 ruling + manager
clarification (self-generated prompts, target's own replies as labels, held-out model selection):
- self-distillation: train on the target's greedy continuations (on-policy for exactly what is verified);
- training-time recursion (EAGLE-3 style "training-time test"): unroll the MTP 3-4 steps feeding its own hidden state,
  loss at every depth.
Verification is untouched (exact, full vocab), so outputs are identical; only which tokens are proposed changes.
Draft lm_head/screen and FP8 fc rulings stay as in the champion; the retrained MTP layer is re-quantized to the
checkpoint's 128x128 block FP8 (same bytes, same kernels).

## Upside (argued from measurements)
Step cost of more rows (job 382 + T38-001): +16 rows (k 3->4) ~ +1.4 ms AR (0.7 us/row/AR x 128) + ~0.7 ms (one more
drafter pass) + small ~= +9% step time. With today's head k=4 adds ~0.27 tokens (+10%): a wash (consistent with k=3 being
the champion's choice). With a head at conditional 0.80 / 0.78 / 0.78 / 0.78:
- k=3: 1 + 0.80 + 0.624 + 0.487 = 2.91 tokens (+9% at the same step cost);
- k=4: 3.29 tokens (+23% for +9% step) => +13% decode throughput.
Decode is ~70% of the benchmark (job 382) => **+6% (k=3) to +9% (k=4) overall if the head reaches those numbers**;
more if p1 improves further. Assumed: the target conditional acceptances; measured: everything else.

## Riskiest assumption and cheapest test (milestone 1)
Riskiest: fine-tuning a pretrained one-layer MTP head on ~1M self-generated tokens raises its *greedy* acceptance on
held-out self-generated data materially (target: expected accepted length at k=3 +4% or more offline).
Key enabler: on the target's own greedy outputs, acceptance can be computed OFFLINE exactly (teacher-forced: draft
recursively from the target's hidden states and true tokens, count matches until the first miss), so the test needs no
serving A/B. Steps:
1. Self-generated data: Magpie-style queries sampled from the chat template + a generic hand-written topic list (no
   ShareGPT, nothing selected to resemble it), replies from the champion server (T=0, thinking as default). ~1-1.5M tokens.
   Script + topic list + counts recorded.
2. Dump the target's final hidden states (the MTP's input) for those sequences (vLLM hook / extract_hidden_states).
3. Offline acceptance of the stock MTP on a held-out split, calibrated against the online 2.67 (the proxy must match
   within a few %).
4. Short fine-tune (1 GPU, bf16 master weights of the MTP layer + fc + norms; lm_head/embeddings frozen; recursive unroll
   depth 3-4), re-measure held-out offline acceptance. Kill criterion: < +4% expected accepted length at k=3 and no
   path to k=4 paying.
GPU: ~35 GPU-min (generation ~10, dump ~5, training ~15, evals ~5).
