# T20-1 proposal (leader-20, explore): fence-free tagged decode AR + rank rebalance + drain/glue package

Champion reference: T14-004, 956.6 tok/s. Bar: payoff if it works >= +5% (1004.4).

## Why this, after T2-T19
All earlier write-ups agree that decode sits on coupled HBM/tensor floors, and I re-checked that. I also
re-checked T19's 3.1 ms "inter-step gap" on T14's in-situ nsys (agents/leader-20/idle.py and
gapnames.py on agents/leader-14.w1/insitu/B1/profile.sqlite, CPU only). Decode steps have no hidden GPU
idle. The only large kernel gaps (1659 x ~296 us, ~4% of the window) are copy-engine AR waits in mixed
steps (Marlin -> memcpy -> add_kernel), already counted as T19's exposed comm.

The one decode component that is still far from its *transport* floor is the host AR. Measured:
- KB23: ~21 us write + ~21 us read, run **serially**: 41-42 us/AR at M=48.
- The champion uses `_config` grid 8, K=1 at decode. Every reader block waits for the peer writer
  block's `__threadfence_system` + flag, and all writer blocks finish together. So the read of the
  peer's data cannot start until the whole write has landed.
- KB73 (T15-002): SM write ∥ SM read of 384 KB = **25 us**.

T15/T16 tried to reach that duplex floor with copy-engine writes and lost to CE start latency in
graphs (KB74). Nobody has tried an **all-SM, fence-free, flag-in-data** protocol that streams. T18
costed "LL-style" with a 16 B tag (33% bytes) and doubted 64 B atomicity. My variant needs only:
- 8 B single-copy atomicity, the assumption NCCL's LL protocol already makes over PCIe/host memory (SHM
  transport);
- 1 epoch bit per 8 B word, about 1.6% bytes. The slots are already double-buffered by parity, so a
  parity bit separates the current epoch from stale data from epoch-2.

The reader spins directly on the payload words as they land. Its PCIe reads then overlap the peer's
writes word by word, with no fence and no flag round trip. Exactness: the payload decodes bitwise
(same codec bits), so it is bitwise equal to the champion's AR.

## Roadmap (gated; each step is filed as a record; stop at any failed gate)
1. **G1, tagged-AR microbench (seed, ~6 GPU-min).** 2-process, NUMA-verified slots, real decode payload
   (M=48 x 5120 bf16, compressed). Tagged-stream codec: the existing 0.781 block codec, bit-packed into
   63-bit payload words + 1 epoch bit. Run in a CUDA graph with the prefetch blocks on, against the
   champion hostar in the same job.
   - Interleaved reps, plus a negative control: delay the producer before its copy (KB57); the
     checker must see no stale words.
   - Measure:
     - us/AR standalone;
     - a T4-001-style 16-layer chain with real Marlin shapes, which catches the lost-prefetch-window
       effect.
   - Reuse T16-001's harness (agents/leader-16.w1/h: bench.py/job.sh, arm A_pf = champion hostar +
     prefetch, arm N = no AR).
   - **Gate: >= 6 us/AR saved in the chain on both ranks** (T16-001: A_pf costs 22 us/AR over N in chain).
   - Estimate: 38.5 -> ~26-28 us standalone, ~-6 to -7.5 us in chain after the prefetch loss.
2. **G2, in-server (~15 GPU-min).** Wire it in as a hostar mode for messages <= 600 KB (decode, drafter,
   small mixed steps). Bitwise check vs the champion AR on live activations. Then a same-job ABBA (300
   prompts, 2+2 fresh starts, interleaved) vs T14-004.
   - **Gate: every B above every A.**
   - Then official (20 min reserved).
3. **G3, GPU0/GPU1 rebalance without duplicated weights (~20 GPU-min).**
   - Prefill-heavy (compute-bound) work is paced by GPU0's locked 2235 MHz clock: T19 L2 has rank-0
     Marlin 131 vs rank-1 113 ms at 400-800 tokens.
   - Split the MLP intermediate unevenly (e.g. 7808/9600 of 17408, 64-aligned). That moves ~3.5% of
     GEMM work to GPU1.
   - Compensate decode, which is HBM-bound and would otherwise be paced by GPU1's extra ~0.9 GB/step,
     by giving GPU0 most of the vocab shard of the target lm_head and draft lm_head. These are
     decode-only bytes, custom kernels, and greedy local-argmax.
   - Memory moves between ranks rather than being duplicated (net ~±0.3 GB/rank; tune the shift to
     fit KV 5 GiB).
   - Microbench the per-rank step model first, then ABBA.
4. **G4, harvest small exact items (~20 GPU-min), on top of whatever has landed.**
   - Drain-time adaptive k. Uses T5's two-slot GDN + adaptive-verify plumbing. When fewer than ~10
     requests remain, rows are cheap.
   - The T2-006 mixed-step glue: DMA add fused into FusedAddRMSNorm; GDN index glue -> slices.
   - ABBA each, then one official for the stack.
