## Idea
- The levers left are fewer verify rows per output token, or more accepted tokens per weight pass (T4 write-up, KB62).
  Today: k=2, M=48, E=2.325.
- Two things killed deeper speculation before. T5 measured both on the built engine:
  - The "cliff above M=48" is real, and it is entirely Marlin going from 3 to 4 m-blocks: +3.0 ms in situ.
    GDN, attention and norms at 4 tokens/request add only ~0.2 ms, and the AR +0.6 ms (T5-003).
    It is a step at M=49, flat to M=64, not a per-row cost (T5-002).
  - Memory: k=3 needs ~208 blocks for 16 requests.
- Once the cliff is fixed, k=3's E +16.4% (2.325 -> 2.707 in-server, T5-001) costs only the per-row AR/rest
  (+0.9 ms) plus one draft step (+0.85 ms), i.e. ~+7% step for +16% tokens.
- Then budgeted verification fills M=64 with the best slots of K_MAX=4 drafts per request (T3-2's design, now at M=64).
- The Marlin cliff kernel is T6's agreed scope (leader-6, proposals/T6-1.md). T5 owns the speculation policy,
  the memory fix and the drafter. Agreed by message 2026-11-09.
- Exact by construction: verification is unchanged greedy target verification. Only the number and choice of
  drafted slots change.

## Roadmap
1. **(~6 GPU-min) Settle the memory price.**
   - Repeat A (champion) vs C (cap 1024) and test caps 1536/1792 with k=3 at KV 5.75 GiB, interleaved.
   - If a cap above 1024 fits and costs <~1%, that is the cheap memory route.
   - In parallel, code-read route B: one materialized GDN state slot per request instead of 1+k
     (mamba_utils.py align copies, gdn_replay_flush modes 0/1, the replay no-log fallback reading S[accepted-1]).
2. **(~15 GPU-min) k=3 + per-shape Marlin tile override** ({64,128,128} for gate_up/gdn_out/attn_o at 4 m-blocks)
   + the memory route. Same-job ABBA vs T1-042, GSM8K-50, 128K. This is the first candidate that could beat the
   champion on its own: an expected ~+2-4%.
3. **(~10 GPU-min) Route B** if step 1 says the graph cap costs >1%. Bitwise check of states against stock slots on
   single requests, plus 128K (it crosses 1600-token boundaries).
4. **(~25 GPU-min) Confidence-budgeted K_MAX=4 at M<=64.**
   - Sharded draft confidence folded into the local-argmax gather; on-GPU top-B slot selection; ragged verify.
   - GDN replay kMaxLogTokens 4 -> 5.
   - First an offline sim on T3's held-out data (CPU, 0 GPU) to size the E gain at B=48 vs fixed k=3.
5. **Stack on T6's M=49-64 Marlin kernel when it lands.** Official eval (~20 GPU-min) whenever a candidate beats
   T1-042 consistently.
