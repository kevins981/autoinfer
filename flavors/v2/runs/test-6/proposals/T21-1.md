## What earlier teams missed (measured, CPU + job 141)
- The model's chat template (chat_template.jinja l.46-52; bank/T21-001/template_excerpt.txt) injects a default system prompt whenever thinking is on, which is the default.
- So all 400 requests share a **45-token prefix**: 18.0K of 104.8K prompt tokens (17%). I tokenized vLLM's own ShareGPT sample (seed 0): agents/leader-21/prompt_lens.txt.
- The champion re-prefills it every time. Prefix caching is on but hits **0.0%** (T14-004 official metrics: 0 of 104,718). Hybrid attention blocks are 1600 tokens and align-mode GDN checkpoints sit only on 1600-token boundaries.
- The stock off-by-default fix doesn't work here. `--prefix-match-unit 16 --enable-mamba-shared-prefix-checkpoint` (bank/T21-001, job 141) gave 144 hit tokens of 104,718 and 917 tok/s (~-4%, cross-job n=1). Each hit is 16 tokens, because the EAGLE/MTP margin drops one unit, and the junction stops seem to cost extra steps.

## Roadmap
- **M1. Working prefix-state cache** (code; needs the ruling).
  - A token-granular junction checkpoint (GDN recurrent + conv state for 48 layers + attention/MTP KV of the prefix), held outside the evictable pool (~75 MB/rank for each checkpoint, LRU of a few).
  - Created by live traffic only: the second request sharing a prefix ends one chunk at the junction. No warm-up.
  - On a hit: copy the state into the request's slot and start the prefill at the junction. That is the same math as chunked prefill.
  - Checks: GDN state after resume vs a full prefill (max-abs diff), GSM8K-50, a 128K pass (memory moved).
  - **Gate G1:** >= 40 hit tokens on >= 95% of requests, and same-job A/B >= +2.5% vs T14-004.
- **M2. Prompt tokens as forced-accepted draft rows** (no ruling needed).
  - A request whose remaining prompt is short (<= ~45 tokens after the M1 hit) never gets a mixed step. Each decode step feeds its next 3 prompt tokens as [row, "draft", "draft"] with acceptance forced, so the batch stays a uniform 16x3 decode step (FULL graph, M=48, no extra rows).
  - The last prompt position's argmax is the first output token.
  - Exactness: the same causal math on the spec-verify kernels (attention, GDN recurrent instead of chunked). The checks are max-abs/bitwise vs the mixed-step prefill on the same prompt, plus GSM8K.
  - **Gate G2:** same-job A/B >= +1.0% on top of M1.
- **M3.** Stack, same-job ABBA (2+2 fresh starts), GSM8K-50, 128K, then official.
